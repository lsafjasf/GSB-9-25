## API 概览

```python
from eventbus import EventBus

bus = EventBus()
sub = bus.subscribe("evt", handler, once=False, weak=False, filter=None)
bus.unsubscribe("evt", handler)   # 或 sub.cancel()，均幂等
errors = bus.publish("evt", *args, **kwargs)  # 返回异常列表
```

- 事件类型：任意可哈希对象，空字符串 `""` 合法；对无订阅者的类型发布是空操作。
- `once=True`：仅投递一次后自动注销；并发发布下保证至多投递一次。
- `filter`：谓词，与回调同参，返回 `False` 跳过本次投递。与 `once` 组合时，过滤器通过才消耗一次性订阅——不匹配（或过滤器抛异常）的事件不会用掉这次机会。
- `weak=True`：弱引用回调（绑定方法用 `WeakMethod`），对象回收后订阅自动失效并清除。

## 生命周期与投递语义

**投递顺序与并发模型**
- 订阅顺序即投递顺序（按订阅先后串行调用）。
- 单个 `publish` 调用内**不做并发投递**；多个线程并发 `publish` 时，各轮的投递可能交错，订阅者需自行保证线程安全。订阅列表结构由总线内部锁保护，并发发布/订阅/取消不会破坏其结构。

**快照语义（发布期间修改订阅列表）**
- `publish` 开始时对当前订阅列表取快照。
- 发布期间**新增**的订阅者：本轮不投递，下一轮起生效。
- 发布期间**移除**的订阅者：本轮即不再被调用。
- 因此不会重复投递，也不会漏投递（相对快照而言）。

**取消语义**
- 取消立即生效：投递循环在调用每个订阅者前检查其状态，本轮中已被取消的一律跳过。
- 重复取消不报错（`cancel()` / `unsubscribe()` 均幂等）。
- 订阅者自取消：本轮已执行的调用不受影响，自身后续轮次不再被调用。
- 订阅者取消排在其后的其他订阅者：后者本轮即被跳过（确定规则：以调用时刻的存活状态为准）。

**异常语义**
- 订阅者或过滤条件抛出的异常不中断本轮其余订阅者的投递。
- 所有异常按发生顺序汇总，作为列表由 `publish` 返回（空列表表示无异常）。
- `once` 订阅即使回调抛异常也会被注销。

**弱引用与回收**
- `weak=True` 时不持有订阅对象，对象可被 GC 回收；回收后订阅自动从注册表清除，后续发布不再调用。
- 默认（强引用）订阅会阻止对象回收——这正是弱引用订阅要解决的问题。
- 注意：弱引用普通函数/lambda 时，调用方需自行保持引用，否则订阅会立即失效。

**递归发布**
- 订阅者内可递归 `publish` 同类事件：每次发布独立取快照，行为确定（内层发布看到当时的订阅列表），不会损坏订阅表状态。
- 注意：实现**没有重入计数或深度上限**。回调里无条件递归发布会一路嵌套调用，直至触发 `RecursionError`。递归发布的回调必须自带终止条件（如计数器或状态判断）。

## 测试覆盖

- 基本：订阅/发布/顺序、事件隔离、`once`、`filter`、`once`+`filter` 组合（不匹配/过滤器异常不消耗订阅）、按回调取消、幂等取消、空事件类型
- 取消即时性：本轮取消后续订阅者、自取消、跨线程取消竞争
- 异常：多异常汇总、不中断他人、filter 异常、once 抛异常仍注销
- 发布期变更：新增本轮不投递、移除本轮跳过、递归发布同类事件
- 弱引用：可回收性（GC 后自动注销）、存活期正常投递、强引用对照
- 并发：8 发布线程 × 500 次 + 4 订阅/取消搅动线程，计数精确、结构完好；并发下 `once` 恰好一次
