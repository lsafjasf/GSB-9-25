# GSB-9-25

分块内存有序索引（Python 3，仅标准库），支持点删与**范围删除**，写操作快照隔离、并发读安全。

## 设计

- `sorted_index.py` — 索引库
  - 存储为有序块链表，每块定容槽位数组（keys/vals + count），块间键区间不相交。
  - 块一旦发布即不可变；所有写操作（put / delete / delete_range）对受影响块做 copy-on-write，然后在写锁内以单次引用替换发布一个 `_Version` 版本对象（块列表 + 块起始键 + size 三者绑定）。读者每次操作只加载一次该引用，因此永远看到自洽的单一版本：要么删除前完整状态，要么删除后完整状态，绝不看到中间态。
  - `delete_range(lo, hi)`：半开区间 `[lo, hi)`。完全被覆盖的块整块丢弃（容量立即归还分配器），部分覆盖的边界块按存活键精确重建。返回删除条数。
  - 点删保留块的槽位容量，释放的槽位可被后续插入复用（统计中体现为 fragmentation）。
  - `stats()` 返回 `size / capacity / blocks / fragmentation`；`snapshot()` 返回不可变一致视图。

## 运行

```bash
python3 -m unittest discover -s tests -v   # 边界 / 对拍 / 并发读 / 容量复用测试
python3 bench_delete.py                    # 10 万条删除性能对比 + 回收证据
```

## 测试覆盖（tests/test_sorted_index.py）

- 边界：空区间、区间越界、覆盖全表、跨大量分块、相邻区间连续删除、边界落在块内、空索引。
- 对拍：60 组随机键集合 + 随机区间，范围删除 vs 逐条删除，比较剩余键集合、size 完全一致，且范围删除 capacity 不大于逐条删除；另有 3000 步随机混合负载与 dict 对拍。
- 并发读：4 个读者线程在范围删除期间持续取快照，断言每次扫描结果等于删除前或删除后的完整键集合（含边界键与 size 的一致性）；另有 200 次相邻范围删除下的快照一致性（有序、唯一、size 一致、键值对应），以及点读（`in` / `get`）在 190 次相邻范围删除期间对保留键永不误报缺失、永不返回错误值。
- 回收：范围删除后 capacity 同步下降；点删释放的槽位被后续插入复用，capacity 零增长。

## 实测数据（本机，200k 键删中间 100k）

- 范围删除 ~4.5 ms，逐条删除 ~1183 ms，约 264x。
- 范围删除后 capacity 200,704 → 100,704，存活块对象 196 → 99（gc 验证）。
- 5 万条点删后再插入 5 万条，capacity 增长为 0。
