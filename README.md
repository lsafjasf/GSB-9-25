# GSB-9-25 路由库（Python 3，仅标准库）

段 trie 路由器：支持参数段、单段/尾部通配、方法与主机前缀过滤、完备优先级、
加载期冲突检测、严格百分号解码。无任何第三方依赖。

## 规则语法

文本格式每行一条：`METHOD HOST PATTERN`（`*` 或 `-` 表示任意，`#` 为注释）。

```
GET  api.   /users/{id}
POST -      /users/{id}/orders/{oid}
*    -      /static/**
GET  -      /health
```

- 静态段：`/users/list`，字面匹配。
- 参数段：`{name}`，匹配任意单个段，匹配后提取为参数。
- 单段通配：`*`，匹配任意恰好一个段。
- 尾部通配：`**`，必须是最后一段，匹配零个或多个剩余段。
- 方法：精确匹配（大小写不敏感），`*` 匹配任意方法。
- 主机前缀：如 `api.` 匹配 `api.example.com`；`*` 匹配任意主机。

## 优先级（完备且可解释）

1. 先按方法与主机前缀过滤，不满足约束的规则不进入候选。
2. 候选规则按「段类型元组」字典序比较：静态段(0) < 参数段(1) < 单段通配(2) < 尾部通配(3)，
   从第一段起逐段比较，首个不同处类型小者胜。即：**静态段优先于参数段，参数段优先于通配**。
3. 段类型元组完全相同（同一 trie 终止节点）时，**按注册顺序**，先注册者胜。

`match()` 返回的 `Match` 对象中：

- `rule`：命中的最高优先级规则；`params`：提取的参数（`name`/`raw`/`value`）。
- `hit_order`：全部候选规则按命中优先级排列（胜者在前）。
- `shadowed`：同样匹配但优先级落败的候选规则，即被遮蔽的候选。

## 参数解码

参数值做严格的百分号解码（UTF-8，`errors="strict"`）：

- `raw` 保留原始形式，`value` 为解码结果；`+` 在路径中按字面处理（不转空格）。
- 非法 `%XX` 序列或非法 UTF-8 字节不会透传为普通字符串，而是抛出
  `DecodeError`，其中 `segment_index` 指出出错的段位置（0 起）。

## 加载期冲突检测

`add_rule()` / `load_rules()` 在加载时检测「完全被前序规则遮蔽」的无意义规则并拒绝，
报错含行号与被谁遮蔽。判定条件（对每条可能命中新规则 B 的请求，都存在已注册规则 A
使得 A 也命中且优先级不低于 B）在 trie 上精确求值：

- 按「段类型元组」字典序（与匹配时同一套顺序关系）：A 在首个不同段的类型
  更小时即整体胜出，后续段只需覆盖 B 的剩余路径，不再逐段要求类型更强
  （如已有 `/{x}/**` 遮蔽后来的 `/*/foo`；但 `*` 不遮蔽后来的 `{x}`，
  `{x}` 也不遮蔽后来的静态段）。
- 约束：A 的方法为任意或与 B 相同；A 的主机前缀为任意或是 B 前缀的前缀。
- `**` 仅被同节点相同的 `**` 遮蔽；完全重复的规则（同方法/主机/模式）视为冲突。

示例：

```
GET - /a/{x}     # line 1
GET - /a/*       # line 2 -> ConflictError: line 2 ... fully shadowed by line 1
```

## 数据结构

段 trie（前缀树）：每个节点持有 `static` 子节点字典（O(1) 查找）、至多一个参数
子节点、至多一个通配子节点，以及终止于该节点的规则列表与 `**` 规则列表。
匹配时沿路径逐段下行，每层按 静态→参数→通配 的顺序 DFS，自然按优先级字典序产出
候选，再按方法/主机前缀过滤。**从不线性扫描全部规则**；耗时取决于路径深度与候选
分支数，与规则总数基本无关。

## 规模与耗时

`python3 bench.py [规则数] [查询数]`，本机（Python 3.12）实测，20000 次查询取平均：

| 规则数 | trie 单次匹配 | 线性扫描基线 | 加速比 |
|-------:|--------------:|-------------:|-------:|
| 1,000  | 0.74 µs       | 28.4 µs      | 38x    |
| 2,000  | 0.94 µs       | 59.6 µs      | 64x    |
| 5,000  | 1.26 µs       | 165.3 µs     | 131x   |

trie 耗时随规则数近似平坦（仅随路径深度/分支微增），线性扫描随规则数线性增长。

## 运行

```bash
python3 -m unittest test_router -v   # 25 项自测
python3 bench.py 2000 20000          # 规模基准
```

## 文件

- `router.py`：路由库（模式解析、trie、匹配、解码、冲突检测、文本加载）。
- `test_router.py`：unittest 自测（匹配/优先级/解码/冲突检测/千条规模冒烟）。
- `bench.py`：规模基准，内含线性扫描对照实现。
