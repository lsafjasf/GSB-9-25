# 整数序列游程/差分编码库（intcodec）

面向监控指标这类「时间戳递增、相邻数值变化很小」的整数序列，提供
**差分编码（DELTA）**、**游程编码（RLE）**、**差分+游程组合（COMBO）**
以及**原样（RAW）**四种模式，自动按数据特征选择；仅依赖 Python 3 标准库。

## 文件

| 文件 | 说明 |
|---|---|
| `intcodec.py` | 库：变换、帧序列化、自动模式选择与选择依据 |
| `selftest.py` | 对拍自测：逐元素参考实现、随机往返、边界、坏帧、百万耗时 |
| `benchmark.py` | 分布敏感性基准（体积对比 + 耗时），可 `--json` 落盘 |
| `sensitivity.json` | 一次实测的机读数据（Python 3.12.3, n=1,000,000） |
| `chunk_bench.py` | 分块数对压缩率影响基准（三类数据 × 1~65536 块 + 自适应） |
| `chunk_sensitivity.json` | 分块扫描的机读数据（Python 3.12.3, n=1,000,000） |

## 快速运行

```bash
python3 selftest.py                  # 对拍 + 边界 + 百万级往返/耗时
python3 benchmark.py                 # 分布敏感性表格
python3 benchmark.py --json out.json # 额外输出机读数据
python3 chunk_bench.py               # 分块数 vs 压缩率扫描（含分块/整段对拍）
python3 intcodec.py "100,110,120,120,120,9,9,9,9"   # 单序列演示
```

## API

```python
import intcodec as ic

blob, report = ic.encode_auto(seq)   # 自动选择，report 含选择依据与四模式体积
seq2   = ic.decode(blob)             # 按帧头自描述模式解码
blob_r = ic.encode(seq, ic.RLE)      # 也可强制 RAW/DELTA/RLE/COMBO

# 分块自适应（CHUNKED 帧，decode 透明识别）
blob_c, rep = ic.encode_chunked(seq, chunk_size=4096)      # 固定块
blob_c, rep = ic.encode_chunked(seq, adaptive=True,
                                block_size=1024)           # 自适应块
seq2 = ic.decode(blob_c)               # 与整段帧同一入口
table = ic.parse_chunk_table(blob_c)   # 只解析块表（模式/元素数/偏移）

# 元素级原语（可与自己的容器/传输格式组合）
d = ic.delta_encode(seq);  ic.delta_decode(d)
r = ic.rle_encode(seq);    ic.rle_decode(r)
c = ic.combo_encode(seq);  ic.combo_decode(c)
```

`report["choice"]` 是人类可读的选择依据；`report["sizes"]` 是四种模式的
真实编码字节数；`report["combo_worse_than_raw"]` 标记组合模式是否劣化。

## 帧格式（自描述）

```
magic b"IC01" | mode:1B | body
  RAW   : n(uvarint), n 个 zigzag-varint 原值
  DELTA : n, 首值 + (n-1) 个差分（zigzag-varint）
  RLE   : 游程数 r, r 组(值 zigzag-varint, 计数 uvarint)
  COMBO : 同 RLE，但游程作用在「首值+差分」序列上

分块自适应帧 mode=4 (CHUNKED)：
  chunk_count(uvarint) | 块表 | 各块 body 顺序拼接
  块表每项: mode(1B) + elem_count(uvarint) + body_len(uvarint)
```

- 整数用 **ZigZag + 无符号 LEB128**：先把符号映射为无符号
  （`x>=0 → 2x`，`x<0 → -2x-1`，解码 `u&1 → -(u+1)/2`），再变长编码。
- **不使用任何固定位宽掩码或带符号移位**，Python 任意精度 int 无损；
  已对 `±2^63`、`±2^127`、`±2^256`、`±2^512` 做往返对拍。
- 解码校验：magic、模式字节、varint 截断、游程计数 >0、相邻游程值不同、
  帧尾无多余字节，任一不满足抛 `CodecError`。
- 分块帧解码先整体校验块表（模式字节、元素数/body 长度 >0、各块 body
  偏移不越界、body 总长与帧长一致），再逐块解码并核对元素数；
  **块表损坏的报错带块序号与字节偏移**，例如
  `块表损坏：块#3 的模式字节非法（值=9，表项位于偏移 42）`。

## 分块自适应（CHUNKED）

整段模式对「分布突变」的混合数据只能全局选一种模式，分块后每块独立选择：

- **固定分块** `chunk_size=k`：切分简单，块表开销约 3~5 B/块。
- **自适应分块** `adaptive=True`：先按 `block_size` 切基础块逐块选最优模式，
  再把最优模式相同的相邻块合并 —— 分布均匀段自动并成大块（块表小），
  分布突变处自然断块（逐块最优）。
- 块内模式选择规则与整段 `analyze()` 完全一致（同字节规则、同平局优先级），
  因此**单块帧与整段帧模式选择一致**；`selftest.py` 对全部生成器 ×
  固定/自适应/单块配置做「分块解码 == 整段解码 == 原序列」对拍。

### 分块数对压缩率的影响（n = 1,000,000，实测）

`vs 整段最优` = 该档总字节 / 整段 AUTO 帧字节；`vs fixed64` = 总字节 / 8n。

**递增时间戳**（整段最优 COMBO 998,814 B）：

|---:|---:|---:|---:|---:|---|
| 1 | 8 | 998,822 | 1.0000x | 0.1249x | COMBO:1 |
| 64 | 321 | 996,271 | 0.9975x | 0.1245x | DELTA:35 COMBO:29 |
| 1,024 | 5,122 | 996,478 | 0.9977x | 0.1246x | DELTA:527 COMBO:497 |
| 16,384 | 48,392 | 1,083,343 | 1.0846x | 0.1354x | DELTA:10090 COMBO:6040 |
| 65,536 | 187,503 | 1,440,500 | 1.4422x | 0.1801x | DELTA:47211 COMBO:15289 |
| 自适应(507块) | 2,537 | 990,764 | 0.9919x | 0.1238x | DELTA:253 COMBO:254 |

**小波动游走**（整段最优 DELTA 1,000,010 B）：

| 分块数 | 块表开销 | 总字节 | vs 整段最优 | vs fixed64 | 块内模式 |
|---:|---:|---:|---:|---:|---|
| 1 | 8 | 1,000,018 | 1.0000x | 0.1250x | DELTA:1 |
| 256 | 1,282 | 1,002,311 | 1.0023x | 0.1253x | DELTA:256 |
| 4,096 | 20,412 | 1,036,745 | 1.0367x | 0.1296x | DELTA:4082 |

| 自适应(1块) | 8 | 1,000,018 | 1.0000x | 0.1250x | DELTA:1 |

**剧烈震荡 ±1e9**（整段最优 RAW 4,865,231 B）：

| 分块数 | 块表开销 | 总字节 | vs 整段最优 | vs fixed64 | 块内模式 |
|---:|---:|---:|---:|---:|---|
| 1 | 9 | 4,865,240 | 1.0000x | 0.6082x | RAW:1 |
| 1,024 | 5,122 | 4,868,018 | 1.0006x | 0.6085x | RAW:632 DELTA:392 |
| 16,384 | 64,521 | 4,923,764 | 1.0120x | 0.6155x | RAW:9364 DELTA:6766 |
| 65,536 | 187,503 | 5,071,822 | 1.0425x | 0.6340x | RAW:39319 DELTA:23181 |
| 自适应(462块) | 2,376 | 4,864,138 | 0.9998x | 0.6080x | RAW:231 DELTA:231 |

结论：

1. **分布均匀时分块无收益**，块表开销随块数线性上涨（每块约 3~5 B），
   65,536 块时仅块表就 ~187 KB，压缩率明显变差；分块数应按分布变化点
   的数量级选择，而非越多越好。
2. **自适应切分在三类数据上都不劣于整段**（均匀时自动合并成 1 块或
   少数大块），是安全的默认选择。
3. **分块的真正收益在混合分布**：40 万递增时间戳 + 30 万恒定值 +
   30 万剧烈震荡（n=1,000,000）实测 —— 整段 AUTO 只能全局选 DELTA
   （2,160,700 B），自适应分块（135 块，RAW/DELTA/RLE/COMBO 各得其所）
   为 1,859,650 B，**再省 13.9%**。

## 模式选择说明

`analyze()` 用与序列化完全相同的规则计算四种模式的实际字节数，取最小；
平局优先级 RAW < DELTA < RLE < COMBO（少做事优先）。

- **RAW**：所有变换都不小于原样（随机/震荡数据）。
- **DELTA**：差分集中在小值（`|Δ|≤63` 时 varint 仅 1 字节），但游程不多。
- **RLE**：长游程多，`(值,计数)` 折叠最省（全相同、块状指标）。
- **COMBO**：差分后出现长游程——分段线性、恒定采样间隔。
- **劣化回退**：规则保证 `COMBO ≥ RAW` 时绝不选 COMBO（`min` 不可能选中），
  自动回退 RAW；该判定同时以 `combo_worse_than_raw` 和中文说明输出。
  解压端无需额外标志：帧头第 5 字节就是模式，直接识别。

## 分布敏感性实测（n = 1,000,000，字节，含 5B 帧头）

`fixed64` = 8×n 定长基线。

| 分布 | fixed64 | RAW | DELTA | RLE | COMBO | AUTO |
|---|---:|---:|---:|---:|---:|---|
| 时间戳(间隔轻微抖动) | 8,000,000 | 5,000,008 | **1,000,012** | 6,000,008 | 1,000,558 | DELTA |
| 平稳小抖动游走 | 8,000,000 | 3,000,008 | **1,000,010** | 3,426,492 | 1,714,716 | DELTA |
| 分段线性(恒定长间隔) | 8,000,000 | 5,000,008 | 1,235,976 | 6,000,008 | **215** | COMBO |
| 全相同 | 8,000,000 | 1,000,008 | 1,000,008 | **10** | 12 | RLE |
| 块状长游程 | 8,000,000 | 1,000,008 | 1,000,500 | **10,226** | 17,919 | RLE |
| 二值交替 | 8,000,000 | **3,000,008** | 4,000,007 | 4,000,008 | 5,000,007 | RAW（COMBO 劣化） |
| 全不同(等差大间隔) | 8,000,000 | 4,112,914 | **3,313,842** | 5,112,914 | 3,980,605 | DELTA |
| 剧烈震荡 ±1e9 | 8,000,000 | **4,864,567** | 4,869,917 | 5,864,567 | 5,869,917 | RAW（COMBO 劣化） |
| 随机小值 [-64,63] | 8,000,000 | **1,000,008** | 1,250,214 | 1,984,002 | 2,242,364 | RAW（COMBO 劣化） |
| 64 位全范围随机 | 8,000,000 | **9,495,768** | 9,558,398 | 10,495,768 | 10,558,398 | RAW（COMBO 劣化） |

### 什么情况下会变大

1. **差分不减量级**：震荡/随机数据的 `|x[i]-x[i-1]|` 与 `|x[i]|` 同分布，
   DELTA/COMBO 不缩小 varint；COMBO 每个长度 1 的游程还要额外附计数，
   必然大于 RAW（见表中交替、震荡、随机三行）。
2. **高熵大整数相对定长 int64 基线膨胀**：64 位全范围随机值经 ZigZag 后
   varint 平均约 **9.5 字节/值**（≥2^63 的 u 值需要 10 字节组），
   RAW 为 9,495,768 B ≈ **1.187×** 8B 定长。即「变长编码」本身在高熵大整数
   上有代价；变换模式代价更高。选择器此时回退 RAW，保证只付最小代价。
3. **反例对照**：分段线性 COMBO 把 8MB 压到 **215 B（约 3.7 万倍）**，
   全相同 RLE 为 **10 B**。

## 自测覆盖

`selftest.py` 对 6 类生成器 × 多种子 × 多种长度（含 0/1/2/3 与 4096）做：
库实现与逐元素朴素参考实现的 **delta/rle/combo 正反变换对拍**、四模式帧
逐元素往返、AUTO 帧头一致性、劣化保护断言；固定边界含空序列、单元素、
全相同、`±2^63`、`±2^256`、`±2^512`；并验证坏 magic/坏模式/截断帧/非 int
输入被拒绝，以及 1,000,000 元素往返与耗时。
分块部分另覆盖：固定/自适应/单块/显式区间四种切分与整段模式的逐元素
对拍、块表元素总数校验、非法区间拒绝，以及 8 类块表损坏（模式字节、
body 长度、元素数、表截断、帧截断、尾部脏字节、body 内容、非分块帧）
的**可定位报错**（错误信息含块序号与字节偏移）。
