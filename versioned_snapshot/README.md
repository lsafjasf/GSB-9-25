# versioned_snapshot — 内存数据结构版本化快照库

Python 3 标准库实现，基于**路径复制写时拷贝（path-copying COW）**的持久化数据结构。

## 原理

- 数据是不可变嵌套 `dict`/`list`；每次修改只复制根到目标节点路径上的容器，
  未变化子树通过引用在版本间共享。
- `snapshot()` 仅记录根引用，O(1)；修改开销 = O(路径深度)，与总数据量无关。
- 强隔离：任何写入都产生新节点，历史版本的根永远不被原地修改；
  `checkout()` 回退后继续写入同样走 COW，不污染任何版本。
- 回收：`delete_version()` 移除根引用后，该版本独占的节点引用计数归零，
  由解释器自动回收；共享节点因仍被其他版本引用而存活。

## API

```python
from snapshot_lib import VersionedStore

s = VersionedStore({"user": {"name": "alice"}})
v0 = s.snapshot()                 # 创建快照，返回版本号
s.set(("user", "name"), "bob")    # 修改（COW）
v1 = s.snapshot()
s.checkout(v0)                    # 回退到任意版本
d = s.diff(v0, v1)                # d.added / d.removed / d.modified
s.delete_version(v1)              # 删除版本，回收其独占数据
s.view(v0)                        # 某版本的普通 dict 视图
```

## 运行

```bash
python3 -m unittest test_snapshot_lib -v   # 测试（隔离断言 + 回收 + 边界情形）
python3 bench.py                            # 全量复制 vs 增量快照耗时/内存对比
```

## 测试覆盖（14 项）

- 隔离性：快照后写入不泄漏、回退后修改不污染其他版本、外部原地改传入对象不影响库内
- 场景：连续多快照、无变化快照（共享同一根，零额外节点）、回退到初始版本、深层嵌套修改
- diff：新增/删除/修改（含嵌套与列表）
- 回收：删除中间版本回收独占节点、共享节点保持存活、删到只剩一个版本；
  回收后断言 `存活节点数 == 剩余版本可达节点数` 且剩余版本视图正确
